# ComfyUI Node Integration

将用户指定的本地代码目录接入统一的 ComfyUI 节点集合。把每个节点族视为向后兼容的公共接口：已有节点 ID、输入名、输出名、返回顺序和默认值不得因整合而改变。

## 收集事实

1. 确认源目录、目标节点集合目录、GitHub 目标仓库与公开/私有意图。用户没有指定集合目录时，定位现有 `ComfyUI-Dakun333-Nodes`；不要擅自并入无关节点库。
2. 先阅读源项目 README、安装说明、许可证和依赖；检查 Git 状态、远端与追踪分支。复制目录先确认没有用户未提交的修改。
3. 搜索密钥、绝对本机路径、模型权重、网络地址和缓存。不要提交 `.env`、令牌、模型或 `__pycache__`。
4. 核对许可证、来源和版权。许可证不明确或与目标仓库不兼容时，暂停发布并向用户确认。

## 整合节点

1. 将一个节点族放到独立的 Python 模块，保留源节点的注册 ID 和 ComfyUI 输入/输出契约。
2. 在集合根 `__init__.py` 聚合 `NODE_CLASS_MAPPINGS` 和 `NODE_DISPLAY_NAME_MAPPINGS`。为各节点族隔离导入失败，记录清晰错误；检测重复节点 ID 并中止，不能静默覆盖。
3. 遵循 ComfyUI 数据约定：`IMAGE` 为 BHWC、0–1 float，`MASK` 为相应掩码。明确批次语义；支持批次时保持批次数，不能支持时抛出清晰错误。
4. 合并最小必要第三方依赖到 `requirements.txt`。不要把 ComfyUI 自带的 `torch` 或机器特定 Python/模型路径写入项目依赖或代码。
5. 更新 `pyproject.toml` 的版本、说明、项目 URL 与 Comfy 元数据，使 Repository URL 与实际远端一致。

## 文档与验证

1. 用中文更新 README：安装步骤、节点搜索名称、分类、输入输出、参数范围、调参建议、限制与来源。
2. 更新或新增 `docs/ADDING_NODES.md`，记录可复用的接入、测试和发布清单。
3. 添加或更新最小测试：根包动态导入、注册表完整性、每个新节点的典型输入；图像节点额外验证形状、数值有限性和批次行为。
4. 运行语法编译、测试、`git diff --check` 和敏感文件检查。若只能在与 ComfyUI 不同的 Python 环境验证，明确记录验证边界；不要声称已在 ComfyUI UI 中运行。

## Git 与 GitHub

1. 保留现有 Git 历史和用户改动；先检查状态、远端、分支和 fetch 状态。不得 reset、clean、force push 或覆盖未提交文件。
2. 仅在用户要求发布时创建仓库、提交和推送。默认使用 `ComfyUI-<功能>` 形式的公开仓库，除非用户指定名称或可见性。
3. 在 Windows PowerShell 中使用 `gh` 与 HTTPS 凭据；不得显示或写入 token。推送失败时保留本地提交，优先排查网络和凭据。
4. 推送后检查远端 URL、默认分支、README、提交 SHA 和仓库文件清单。只有用户要求时创建 Release。

## 交付

报告整合的节点、保持的兼容性、依赖、测试结果、远端仓库链接，以及仍未验证的风险。若遇到环境或工具错误，先检索 `debug-expert` 的已知问题；将可复用的新环境问题按该技能的规则记录。
